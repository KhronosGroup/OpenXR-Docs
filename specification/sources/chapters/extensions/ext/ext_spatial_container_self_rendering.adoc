==== Overview

This extension defines "self rendering" for spatial containers.
A self rendered spatial container's pixels are all generated by an app and
submitted to the runtime using standard OpenXR swapchains and composition
layers.
Because spatial containers do not always take up all of a screen's pixels,
the runtime informs apps of each spatial container's recommended resolution
and view configuration to enable apps to render more efficiently.

This extension combined with apiext:XR_EXT_spatial_container is intended to
offer a superset of the capabilities of conventional OpenXR 1.x core
composition layer rendering.
OpenXR 1.x runtimes that support graphical rendering and this extension
must: set
slink:XrSystemSpatialContainerPropertiesEXT::pname:supportsImmersive to true
to indicate they support immersive spatial containers.

==== Spatial Container Rendering Lifecycle

To use self rendering for a spatial container, an app sets the
slink:XrSpatialContainerCreateInfoEXT::pname:graphicsPresentation to
ename:XR_SPATIAL_CONTAINER_GRAPHICS_PRESENTATION_SELF_RENDERING_EXT when
calling flink:xrCreateSpatialContainerEXT.
Then that app can: manage whether a spatial container is actively rendering
by calling the flink:xrBeginSpatialContainerRenderingEXT and
flink:xrEndSpatialContainerRenderingEXT functions.
These functions replace flink:xrBeginSession and flink:xrEndSession.
They are not per-frame operations, such as flink:xrBeginFrame and
flink:xrEndFrame.

Every frame, an app goes through the following steps:

* Call flink:xrWaitFrame and flink:xrBeginFrame.
  These functions have no container-specific structures and function as they
  do in the core spec.
* Retrieve view poses, projection parameters, and rendering recommendations
  for all spatial containers actively rendering with
  flink:xrLocateSpatialContainerViewsEXT.
  For each spatial container, the runtime reports whether its composition
  layers should: be rendered and the recommended way to render the layers by
  filling out slink:XrSpatialContainerViewStateEXT.
* Render pixels into composition layers normally.
  These operations have no container-specific structures.
* Submit composition layers for all spatial containers actively rendering by
  calling flink:xrEndFrame and chaining
  slink:XrSpatialContainerLayerFrameEndInfoEXT.

Destroying an slink:XrSpatialContainerEXT handle implicitly removes it from
the active render set.
An app may: destroy a spatial container even if it made a successful call to
flink:xrBeginSpatialContainerRenderingEXT not associated with a
corresponding call to flink:xrEndSpatialContainerRenderingEXT.
The runtime must: behave as if flink:xrEndSpatialContainerRenderingEXT is
implicitly called if needed early in the implementation of
flink:xrDestroySpatialContainerEXT if it returns successfully.

When an app receives an slink:XrEventDataSpatialContainerClosedEXT event for
a container in the active render set, that app should: call
flink:xrEndSpatialContainerRenderingEXT and destroy the
slink:XrSpatialContainerEXT handle.

==== Locating views via flink:xrLocateSpatialContainerViewsEXT

[open,refpage='xrLocateSpatialContainerViewsEXT',type='protos',desc='Locate views for a set of spatial containers']
--
The flink:xrLocateSpatialContainerViewsEXT function locates views for a set
of spatial containers.

include::{generated}/api/protos/xrLocateSpatialContainerViewsEXT.adoc[]

.Parameter Descriptions
****
* pname:session is the slink:XrSession.
* pname:locateInfo is a pointer to an
  slink:XrSpatialContainerViewsLocateInfoEXT structure.
* pname:viewStateCount is the count of the pname:viewStates array.
* pname:viewStates is a pointer to an array of
  slink:XrSpatialContainerViewStateEXT structures to be populated by the
  runtime.
* pname:viewCount is the count of the pname:views array.
* pname:views is a pointer to an array of slink:XrView structures.
****

This function replaces flink:xrLocateViews, allowing an app to query views
for multiple spatial containers simultaneously.

Views for all spatial containers are returned in the single pname:views
array.
The views are ordered based on the index of the spatial container in the
slink:XrSpatialContainerViewsLocateInfoEXT::pname:viewLocateInfos array,
then the view index for that container.

For example, if an app provides three spatial containers in
slink:XrSpatialContainerViewsLocateInfoEXT::pname:viewLocateInfos:
[square]
* Index 0: ename:XR_VIEW_CONFIGURATION_TYPE_PRIMARY_MONO (1 view)
* Index 1: ename:XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO (2 views)
* Index 2:
  ename:XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO_WITH_FOVEATED_INSET (4
  views)

Then the runtime must: fill out the pname:views array with 7 views:
[square]
* pname:views[0] is the view for container 0.
* pname:views[1] is the left eye view for container 1.
* pname:views[2] is the right eye view for container 1.
* pname:views[3] is the left eye view for container 2.
* pname:views[4] is the right eye view for container 2.
* pname:views[5] is the left eye inset view for container 2.
* pname:views[6] is the right eye inset view for container 2.

If pname:viewCount is not equal to the sum of the view counts for each
spatial container's requested view configuration type, the runtime must:
return ename:XR_ERROR_VALIDATION_FAILURE.

The runtime may: decay the view configuration to a type with fewer views for
optimization purposes (e.g. a container is very far away and small such that
stereo is imperceptible).
If the runtime decays the view configuration, the runtime must: still return
the original number of views for that container, populating the extra views
with duplicates of the decayed views.
For example, if ename:XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO is decayed
to ename:XR_VIEW_CONFIGURATION_TYPE_PRIMARY_MONO, both index 0 and index 1
will contain the single mono view.
Consequently, the total number of views returned in the pname:views array is
independent of if the runtime decided to decay any view configurations or
not.

The runtime should: adapt each slink:XrView::pname:fov returned such that
the frustum is as small as possible while still containing the entire bounds
of the corresponding spatial container.
Runtimes may: return non-symmetrical FOVs, for example if a spatial
container is at an oblique angle to the user's view, or is partially
occluded by another object.
Runtimes may: freely position the target rendering surface for the spatial
container.
Due to the nature of multi-app rendering, where spatial containers are
detached from the user, the runtime may: return slink:XrView values not
suitable for pixel rendering, for example if the spatial container is not
visible on screen there are no valid values to set slink:XrView::pname:fov
to.
In such cases, runtimes must: set
slink:XrSpatialContainerViewStateEXT::pname:shouldSubmitLayers to false.

The runtime returns additional per-spatial container rendering state
information in the pname:viewStates array.
If pname:viewStateCount is not equal to
slink:XrSpatialContainerViewsLocateInfoEXT::pname:viewLocateInfoCount, the
runtime must: return ename:XR_ERROR_VALIDATION_FAILURE.

After the runtime queues an slink:XrEventDataSpatialContainerClosedEXT event
for a spatial container, this function must: return ename:XR_FALSE in
slink:XrSpatialContainerViewStateEXT::pname:shouldSubmitLayers and 0 in
slink:XrSpatialContainerViewStateEXT::pname:viewStateFlags for the
corresponding spatial container.

For spatial containers with actively changing locations in the real world,
the runtime should: take the container's motion into account when filling
out pname:views to minimize reprojection artifacts.

If flink:xrLocateSpatialContainerViewsEXT is called for one or more spatial
containers not currently in the active render set, the runtime must: return
ename:XR_ERROR_SPATIAL_CONTAINER_NOT_RENDERING_EXT.

[open,refpage='XrSpatialContainerViewStateEXT',type='structs',desc='View suitability information for a spatial container',xrefs='xrLocateSpatialContainerViewsEXT']
--
The slink:XrSpatialContainerViewStateEXT structure is populated by calls to
flink:xrLocateSpatialContainerViewsEXT with per-spatial container rendering
suitability information.

include::{generated}/api/structs/XrSpatialContainerViewStateEXT.adoc[]

.Member Description
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain.
* pname:viewStateFlags is a bitmask of elink:XrViewStateFlags.
  These flags have the same purpose as the viewStateFlags in the core
  slink:XrViewState structure.
* pname:viewConfigurationType is an elink:XrViewConfigurationType which
  indicates the view configuration type the runtime is using for the spatial
  container, which runtimes may: decay to a view configuration with a lower
  number of views than the one requested.
* pname:shouldSubmitLayers is an basetype:XrBool32 returned by the runtime.
  If ename:XR_FALSE, the app should: avoid submitting composition for this
  spatial container as it is currently not visible or is in a state where
  rendering is not required.
* pname:recommendedImageExtent is an slink:XrExtent2Di structure
  representing the recommended resolution for the spatial container.
****

As with core OpenXR view location, the app must: check the
slink:XrSpatialContainerViewStateEXT::pname:viewStateFlags to ensure the
position and orientation are valid and tracked before using the view data
for rendering.

The app should: check pname:shouldSubmitLayers and
pname:viewConfigurationType to avoid rendering more than the runtime
recommends.
When pname:shouldSubmitLayers is false, the app changes its rendering
behavior as follows:

* The app must: not read the corresponding slink:XrView::pname:fov.
* The app must: not read pname:recommendedImageExtent.
* The app should: avoid rendering to swapchains and submitting composition
  layers for the corresponding spatial container.
* The app should: set
  slink:XrSpatialContainerLayerEXT::pname:retainPreviousSubmission to true.
  If the app chooses to submit layers anyway, it is up to the runtime to
  determine what it wants to do with the layers (e.g. the runtime may:
  choose to drop them).

pname:recommendedImageExtent is explicitly for layers that will be updated
based on the container position or user's view.
When updating layers with content that depends on the spatial container's
position or user's view (such as normal 3D content), the app should: render
to this smaller viewport instead of the default recommended view size.
When updating layers with content that does not depend on the spatial
container's position or user's view (such as static quad layers), the app
may: safely ignore these values.
For view dependent layers, pname:recommendedImageExtent is a recommendation
to the app from the runtime intended to minimize aliasing and improve
rendering performance.
The app is free to submit at full resolution if it wishes.

The slink:XrExtent2Di::pname:width and slink:XrExtent2Di::pname:height of
pname:recommendedImageExtent must: always be a positive integer less than or
equal to the slink:XrViewConfigurationView::pname:recommendedImageRectWidth
and slink:XrViewConfigurationView::pname:recommendedImageRectHeight of the
slink:XrViewConfigurationView for the spatial container's primary view
configuration.
An app should: not recreate a swapchain solely because
pname:recommendedImageExtent changed, as it is a dynamic hint to the app
specifying the slink:XrSwapchainSubImage::pname:imageRect to use in the
slink:XrSwapchainSubImage of any full resolution composition layers it
submits, and can: change every frame.

==== Submitting layers via flink:xrEndFrame

[open,refpage='XrSpatialContainerLayerFrameEndInfoEXT',type='structs',desc='Enable spatial container rendering for a frame',xrefs='xrEndFrame']
--
In order to render spatial containers, the app must: supply a list of layers
associated with their respective spatial containers to flink:xrEndFrame.
This is accomplished via the slink:XrSpatialContainerLayerFrameEndInfoEXT
structure.
include::{generated}/api/structs/XrSpatialContainerLayerFrameEndInfoEXT.adoc[]

.Member Description
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain.
* pname:containerLayerCount is the count of elements in the
  pname:containerLayers array.
* pname:containerLayers is a pointer to an array of
  slink:XrSpatialContainerLayerEXT structures.
****

The pname:containerLayers array contains an slink:XrSpatialContainerLayerEXT
for each spatial container in the active render set (the containers managed
per-session by flink:xrBeginSpatialContainerRenderingEXT and
flink:xrEndSpatialContainerRenderingEXT).
Each slink:XrSpatialContainerLayerEXT contains a list of
slink:XrCompositionLayerBaseHeader pointers associated with the given
spatial container.
Runtimes may: composite containers in any order they choose, independent of
the order of the pname:containerLayers.
For example, runtimes may: composite containers based on their depth
relative to the user, have a spatial container act as a background layer, or
'pin' a spatial container such that it is always on top regardless of its
depth.
Runtimes may: composite layers using different strategies for spatial
containers in bounded or immersive modes.
For example, runtimes may: precomposite each bounded spatial container's
composition layers into a single stereo quad layer that is combined with all
other containers in a second composition step.

slink:XrFrameEndInfo::pname:displayTime and
slink:XrFrameEndInfo::pname:environmentBlendMode will be applied to all
spatial containers supplied in slink:XrSpatialContainerLayerFrameEndInfoEXT.

When this structure is passed to flink:xrEndFrame by being chained onto
slink:XrFrameEndInfo, the following additional error cases are added based
on the active render set:

* If a spatial container is referenced by more than one element of
  pname:containerLayers, runtimes must: return
  ename:XR_ERROR_SPATIAL_CONTAINER_DUPLICATE_EXT.
* If a spatial container in the active render set is not referenced by an
  element of pname:containerLayers, runtimes must: return
  ename:XR_ERROR_SPATIAL_CONTAINER_MISSING_EXT.
* If a spatial container referenced by pname:containerLayers is not a member
  of the active render set, runtimes must: return
  ename:XR_ERROR_SPATIAL_CONTAINER_NOT_RENDERING_EXT.

Furthermore, if there are any spatial containers in the active render set
and this structure is not chained onto slink:XrFrameEndInfo, runtimes must:
return ename:XR_ERROR_SPATIAL_CONTAINER_MISSING_EXT.

In any of the above error cases, the runtime must: not render any content
for any spatial container.

[NOTE]
====
If no spatial containers are in the active render set, an app can: call
flink:xrEndFrame as long as it is not submitting any composition layers.
====

Note that individual swapchains may: be submitted for multiple containers
via layers in a valid structure, e.g. A quad layer rendered via a single
swapchain submitted to multiple spatial containers.
This case is handled uniformly with other rendering: the runtime must:
render the quad in all such spatial containers.

[open,refpage='XrSpatialContainerLayerEXT',type='structs',desc='Layers associated with a specific spatial container']
--
The slink:XrSpatialContainerLayerEXT structure groups standard composition
layers and associates them with a specific spatial container.

include::{generated}/api/structs/XrSpatialContainerLayerEXT.adoc[]

.Member Description
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain.
* pname:spatialContainer is the slink:XrSpatialContainerEXT identifying the
  target container.
* pname:retainPreviousSubmission is an basetype:XrBool32.
  If ename:XR_TRUE, the runtime will retain the last submitted frame for
  this spatial container.
* pname:layerCount is the number of composition layers in the pname:layers
  array.
* pname:layers is a pointer to an array of
  slink:XrCompositionLayerBaseHeader pointers.
****

When pname:retainPreviousSubmission is ename:XR_TRUE, the runtime must:
reuse the composition layers and swapchain image contents as latched during
the most recent flink:xrEndFrame call where pname:retainPreviousSubmission
was ename:XR_FALSE.
Any subsequent modifications to swapchains used by retained layers must: not
be reflected in the rendered output.

For layers submitted for an individual spatial container (intra-container
rendering), the runtime must: follow the already specified rules for layer
composition ordering.
That is to say the layers within containers must: be drawn in the same order
as they are specified, composed via painter's algorithm.

[NOTE]
====
"Clearing" a spatial container refers to the removal of all content from a
spatial container, resulting in nothing being rendered for that container in
the current frame.
Runtimes must: treat this equivalent to the app submitting transparent black
(all bits 0) for every pixel inside the container.
"Retaining" a spatial container refers to the runtime continuing to display
the most recently submitted set of layers for that container.
====

For each spatial container the app can: specify whether to submit new
layers, retain the previous submission, or clear the spatial container:

* To submit new layers, the app provides a non-zero pname:layerCount and a
  valid pname:layers pointer.
* To clear a spatial container, the pname:layerCount for its entry must: be
  0 and pname:retainPreviousSubmission must: be ename:XR_FALSE.
* To retain the last submitted layers and swapchain images (retaining), the
  pname:layerCount for its entry must: be 0 and
  pname:retainPreviousSubmission must: be ename:XR_TRUE.

This explicit per-container control ensures that the app's intent is clearly
communicated in every frame.

If pname:retainPreviousSubmission is ename:XR_TRUE and pname:layerCount is
not 0, the runtime must: return ename:XR_ERROR_VALIDATION_FAILURE.

If slink:XrSpatialContainerCompositionLayerViewConfigurationEXT is not
chained to an slink:XrCompositionLayerProjection that is part of a spatial
container, the runtime must: return ename:XR_ERROR_VALIDATION_FAILURE.
This structure is only applicable to slink:XrCompositionLayerProjection
layers.
If it is chained to other layer types (e.g. quad or cylinder layers), the
runtime must: return ename:XR_ERROR_VALIDATION_FAILURE.

===== Specifying View Configuration for Projection Layers

[open,refpage='XrSpatialContainerCompositionLayerViewConfigurationEXT',type='structs',desc='Specifies the view configuration for a projection layer in a spatial container']
--
The slink:XrSpatialContainerCompositionLayerViewConfigurationEXT structure
is used to specify the view configuration used to render a projection layer
for a spatial container.

include::{generated}/api/structs/XrSpatialContainerCompositionLayerViewConfigurationEXT.adoc[]

.Member Description
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain.
* pname:viewConfigurationType is the elink:XrViewConfigurationType that was
  used to render the slink:XrCompositionLayerProjection.
****

When submitting an slink:XrCompositionLayerProjection for a spatial
container, the app must: specify which view configuration was used to render
the layer.
This is necessary because the app can: choose each frame whether to render
with the spatial container's primary view configuration or the runtime's
suggested decayed view configuration, if any.

When slink:XrSpatialContainerCompositionLayerViewConfigurationEXT is
chained, the app must: ensure that
slink:XrCompositionLayerProjection::pname:viewCount is a valid view count
for the elink:XrViewConfigurationType specified in the chained structure.
The pname:viewConfigurationType specified in the chained structure must: be
the slink:XrSpatialContainerBeginInfoEXT::pname:primaryViewConfigurationType
specified when the container was begun, or the decayed view configuration
type returned by the runtime in slink:XrSpatialContainerViewStateEXT, or
additional values enabled through an extension.

===== Pixel clipping behavior

[open,refpage='XrSpatialContainerLayerVolumeClippingEXT',type='structs',desc='Specify what volume clipping an app has done when submitting layers']
--
Apps should: inform the runtime if they render pixels outside of a spatial
container's bounds or not by chaining
slink:XrSpatialContainerLayerVolumeClippingEXT when submitting composition
layers.

include::{generated}/api/structs/XrSpatialContainerLayerVolumeClippingEXT.adoc[]

.Member Description
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain.
* pname:volumeClipping is the elink:XrSpatialContainerVolumeClippingEXT the
  app has applied.
****

This structure serves as a hint for if the app renders pixels outside the
bounds of a spatial container.
When a spatial container is in immersive mode, because the bounds are
infinite this hint has no meaning.

For bounded spatial containers using self rendering, the runtime needs to
reason about both the 3D volume bounds and the 2D pixel bounds.
The 3D volume bounds is returned from flink:xrGetSpatialContainerBoundsEXT.
The 2D pixel bounds is the projection of the 3D volume bounds onto each
display for the system.

Runtimes must: discard pixels from swapchain images outside the 2D pixel
bounds, however runtimes must: not discard pixels that are inside the 2D
pixel bounds but outside of the 3D volume bounds.
Stereo effects where content appears to extend beyond or in front of the
container's 3D volume bounds are possible.
Apps may: discard pixels outside of the 3D volume bounds of a bounded
spatial container to reduce depth paradoxes and should: set
pname:volumeClipping based on how they do so.
Depth paradoxes often cause eye strain and user discomfort.

Runtimes may: use pname:volumeClipping to adjust how they display a
particular spatial container.
For example, when set to
ename:XR_SPATIAL_CONTAINER_VOLUME_CLIPPING_STRICT_EXT a runtime could render
rear faces of the 3D volume bounds that would cause depth paradoxes if the
spatial container drew pixels behind the container's 3D volume bounds.

Future extensions may: allow for clipping based the 3D volume bounds if
depth information is submitted.

// Example: Complete lifecycle, view location, and frame submission for spatial containers
PFN_xrBeginSpatialContainerRenderingEXT xrBeginSpatialContainerRenderingEXT; // previously initialized
PFN_xrEndSpatialContainerRenderingEXT xrEndSpatialContainerRenderingEXT; // previously initialized
PFN_xrLocateSpatialContainerViewsEXT xrLocateSpatialContainerViewsEXT; // previously initialized

XrSession session; // previously initialized

// We want to update this container
XrSpatialContainerEXT containerA; // previously initialized with XR_SPATIAL_CONTAINER_GRAPHICS_PRESENTATION_SELF_RENDERING_EXT
XrSpace containerASpace; // previously initialized

// We want to retain this container
XrSpatialContainerEXT containerB; // previously initialized with XR_SPATIAL_CONTAINER_GRAPHICS_PRESENTATION_SELF_RENDERING_EXT
XrSpace containerBSpace; // previously initialized

// 1. Add to active render set when the app is ready to start submitting layers
XrSpatialContainerBeginInfoEXT beginInfoA {
  .type = XR_TYPE_SPATIAL_CONTAINER_BEGIN_INFO_EXT,
  .spatialContainer = containerA,
  .primaryViewConfigurationType = XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO,
};
CHK_XR(xrBeginSpatialContainerRenderingEXT(session, &beginInfoA));

XrSpatialContainerBeginInfoEXT beginInfoB {
  .type = XR_TYPE_SPATIAL_CONTAINER_BEGIN_INFO_EXT,
  .spatialContainer = containerB,
  .primaryViewConfigurationType = XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO,
};
CHK_XR(xrBeginSpatialContainerRenderingEXT(session, &beginInfoB));

// ... Frame Loop ...


XrTime displayTime; // returned from xrWaitFrame

const std::vector<XrSpatialContainerEXT> containers = {containerA, containerB};
const std::vector<XrSpace> containerSpaces = {containerASpace, containerBSpace};
uint32_t containerCount = static_cast<uint32_t>(containers.size());

// 2. Setup individual locate info for each container
std::vector<XrSpatialContainerViewLocateInfoEXT> containerLocateInfos(containerCount, {
  .type = XR_TYPE_SPATIAL_CONTAINER_VIEW_LOCATE_INFO_EXT,
});

for (uint32_t i = 0; i < containerCount; ++i) {
    containerLocateInfos[i].viewConfigurationType = XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO;
    containerLocateInfos[i].space = containerSpaces[i]; // Recommended to use container's own space
    containerLocateInfos[i].spatialContainer = containers[i];
}

// Setup bulk locate info
XrSpatialContainerViewsLocateInfoEXT locateInfo {
  .type = XR_TYPE_SPATIAL_CONTAINER_VIEWS_LOCATE_INFO_EXT,
  .displayTime = displayTime,
  .viewLocateInfoCount = containerCount,
  .viewLocateInfos = containerLocateInfos.data(),
};

// Prepare states to be populated by the runtime
std::vector<XrSpatialContainerViewStateEXT> viewStates(containerCount, {
  .type = XR_TYPE_SPATIAL_CONTAINER_VIEW_STATE_EXT,
});

// Call the dedicated locate views function
// We know the required view count is 2 per container for STEREO
const uint32_t viewsPerConfig = 2;
uint32_t totalViewCount = containerCount * viewsPerConfig;
std::vector<XrView> views(totalViewCount, {.type = XR_TYPE_VIEW});

CHK_XR(xrLocateSpatialContainerViewsEXT(session, &locateInfo, containerCount, viewStates.data(), totalViewCount, views.data()));

// Process results
for (uint32_t i = 0; i < containerCount; ++i) {
    XrBool32 shouldSubmitLayers = viewStates[i].shouldSubmitLayers;
    XrExtent2Di recommendedImageExtent = viewStates[i].recommendedImageExtent;
    XrViewConfigurationType viewConfigurationType = viewStates[i].viewConfigurationType;
    bool isDecayedToMono = (viewConfigurationType == XR_VIEW_CONFIGURATION_TYPE_PRIMARY_MONO);
    if (shouldSubmitLayers) {
        // App is expected to also verify viewStates[i].viewStateFlags has valid orientation/position bits before rendering
        XrView& leftView = views[i * viewsPerConfig];
        XrView& rightView = views[i * viewsPerConfig + 1];
        // If isDecayedToMono is true, left and right will be identical.
    } else {
        // Skip layer submission but retain previous submission when calling
        // xrEndFrame.
    }
}

// 3. Setup projection layer for container A
XrCompositionLayerProjection projectionLayer = {.type = XR_TYPE_COMPOSITION_LAYER_PROJECTION};
// ... standard projection layer setup (space, viewCount, views, etc.) ...

// Specify which view configuration was used to render this specific layer
XrSpatialContainerCompositionLayerViewConfigurationEXT containerViewConfig {
  .type = XR_TYPE_SPATIAL_CONTAINER_COMPOSITION_LAYER_VIEW_CONFIGURATION_EXT,
  // Even if the runtime decayed to MONO, we indicate what we actually rendered
  .viewConfigurationType = XR_VIEW_CONFIGURATION_TYPE_PRIMARY_STEREO,
};

// Chain it to the projection layer
projectionLayer.next = &containerViewConfig;
const XrCompositionLayerBaseHeader* layersA[1] = {reinterpret_cast<const XrCompositionLayerBaseHeader*>(&projectionLayer)};

// Note: In a real app, you are required to submit ALL active containers in the render set.

XrSpatialContainerLayerVolumeClippingEXT containerClippingA = {
  .type = XR_TYPE_SPATIAL_CONTAINER_LAYER_VOLUME_CLIPPING_EXT,
  // Set volumeClipping appropriately for the rendering done.
  .volumeClipping = XR_SPATIAL_CONTAINER_VOLUME_CLIPPING_STRICT_EXT,
};

// Setup container A (Update with new pixels)
XrSpatialContainerLayerEXT containerLayerA {
  .type = XR_TYPE_SPATIAL_CONTAINER_LAYER_EXT,
  .next = &containerClippingA,
  .spatialContainer = containerA,
  .retainPreviousSubmission = XR_FALSE,
  .layerCount = 1,
  .layers = layersA,
};

XrSpatialContainerLayerVolumeClippingEXT containerClippingB {
  .type = XR_TYPE_SPATIAL_CONTAINER_LAYER_VOLUME_CLIPPING_EXT,
  // Set volumeClipping appropriately for the rendering done.
  .volumeClipping = XR_SPATIAL_CONTAINER_VOLUME_CLIPPING_STRICT_EXT,
};

// Setup container B (Explicitly retain previous frame)
XrSpatialContainerLayerEXT containerLayerB {
  .type = XR_TYPE_SPATIAL_CONTAINER_LAYER_EXT,
  .next = &containerClippingB,
  .spatialContainer = containerB,
  .retainPreviousSubmission = XR_TRUE,
  .layerCount = 0, // Required to be 0 when retaining
  .layers = nullptr,
};

// Aggregate all container layers
XrSpatialContainerLayerEXT containerLayers[] = { containerLayerA, containerLayerB };

XrSpatialContainerLayerFrameEndInfoEXT spatialEndInfo {
  .type = XR_TYPE_SPATIAL_CONTAINER_LAYER_FRAME_END_INFO_EXT,
  .containerLayerCount = 2, // Must equal the number of active containers
  .containerLayers = containerLayers,
};

XrFrameEndInfo frameEndInfo {
  .type = XR_TYPE_FRAME_END_INFO,
  .next = &spatialEndInfo,
  .displayTime = displayTime,
  .environmentBlendMode = XR_ENVIRONMENT_BLEND_MODE_ALPHA_BLEND,
  .layerCount = 0, // MANDATORY: Must be 0 for self rendering extension
};

CHK_XR(xrEndFrame(session, &frameEndInfo));

// ... End Frame Loop ...

// 4. Remove from active render set when the container is destroyed or no longer needs rendering
XrSpatialContainerEndInfoEXT endInfoA {
  .type = XR_TYPE_SPATIAL_CONTAINER_END_INFO_EXT,
  .spatialContainer = containerA,
};
CHK_XR(xrEndSpatialContainerRenderingEXT(session, &endInfoA));

XrSpatialContainerEndInfoEXT endInfoB {
  .type = XR_TYPE_SPATIAL_CONTAINER_END_INFO_EXT,
  .spatialContainer = containerB,
};
CHK_XR(xrEndSpatialContainerRenderingEXT(session, &endInfoB));
