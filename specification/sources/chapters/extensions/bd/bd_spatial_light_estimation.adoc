==== Overview

This extension enables applications to retrieve real time light estimation
data of the physical environment through spatial entities.
The spatial entities mentioned in this extension specifically refer to
ByteDance vendor-specific spatial entities, as detailed in the
apiext:XR_BD_spatial_sensing specification.
This extension requires apiext:XR_BD_spatial_sensing to be enabled.

==== Inspect System Capability

[open,refpage='XrSystemLightEstimationPropertiesBD',type='structs',desc='System property for light estimation.',xrefs='XrSystemProperties xrGetSystemProperties']
--

The slink:XrSystemLightEstimationPropertiesBD structure is defined as:

include::{generated}/api/structs/XrSystemLightEstimationPropertiesBD.adoc[]

.Member Descriptions
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain.
* pname:supportsLightEstimation is an basetype:XrBool32, indicating if the
  current system is capable of light estimation.
* pname:supportsEnvironmentTexture is an basetype:XrBool32, indicating if
  the current system supports providing environment texture data.
* pname:supportsSphericalHarmonics is an basetype:XrBool32, indicating if
  the current system supports providing spherical harmonics coefficients.
****

An application can: inspect whether the system is capable of light
estimation by chaining an slink:XrSystemLightEstimationPropertiesBD
structure to the slink:XrSystemProperties::pname:next chain when calling
flink:xrGetSystemProperties.

If a runtime returns ename:XR_FALSE for pname:supportsLightEstimation, the
system does not support retrieving light estimate data, and must: return
ename:XR_ERROR_FEATURE_UNSUPPORTED from flink:xrCreateSenseDataProviderBD
when passing the elink:XrSenseDataProviderTypeBD value
ename:XR_SENSE_DATA_PROVIDER_TYPE_LIGHT_ESTIMATION_BD.

The application should: avoid using light estimation functionality when
pname:supportsLightEstimation is ename:XR_FALSE.

If a runtime returns ename:XR_FALSE for pname:supportsEnvironmentTexture,
the runtime must: return ename:XR_ERROR_FEATURE_UNSUPPORTED from
flink:xrCreateSenseDataProviderBD when the
ename:XR_LIGHT_ESTIMATION_CREATE_ENVIRONMENT_TEXTURE_BIT_BD flag is set in
slink:XrSenseDataProviderCreateInfoLightEstimationBD.

If a runtime returns ename:XR_FALSE for pname:supportsSphericalHarmonics,
the runtime must: return ename:XR_ERROR_FEATURE_UNSUPPORTED from
flink:xrCreateSenseDataProviderBD when the
ename:XR_LIGHT_ESTIMATION_CREATE_SPHERICAL_HARMONICS_BIT_BD flag is set in
slink:XrSenseDataProviderCreateInfoLightEstimationBD.

If the runtime returns ename:XR_TRUE for pname:supportsLightEstimation, the
system supports light estimation.
This implies that
slink:XrSystemSpatialSensingPropertiesBD::pname:supportsSpatialSensing must:
also be ename:XR_TRUE.

Note that pname:supportsLightEstimation may: be ename:XR_TRUE even if
running on an Android-based platform and the application does not have the
required `com.picovr.permission.SPATIAL_DATA` permission both declared in
the manifest and granted at runtime.
Evaluation of permissions takes place later, in the asynchronous operation
started by flink:xrStartSenseDataProviderAsyncBD.

==== Create Light Estimation Provider

[open,refpage='XrSenseDataProviderCreateInfoLightEstimationBD',type='structs',desc='Light estimation provider configuration',xrefs='xrCreateSenseDataProviderBD XrSenseDataProviderCreateInfoBD']
--
The slink:XrSenseDataProviderCreateInfoLightEstimationBD structure is
defined as:

include::{generated}/api/structs/XrSenseDataProviderCreateInfoLightEstimationBD.adoc[]

.Member Descriptions
****
* pname:type is the elink:XrStructureType of this structure.
* pname:next is code:NULL or a pointer to the next structure in a structure
  chain, such as slink:XrEnvironmentTextureCreateConfigInfoBD.
* pname:createFlags is a bitmask of elink:XrLightEstimationCreateFlagBitsBD
  describing light estimation configurations.
****

Applications create an slink:XrSenseDataProviderBD handle representing a
light estimation provider by calling flink:xrCreateSenseDataProviderBD,
setting slink:XrSenseDataProviderCreateInfoBD::pname:providerType to the
elink:XrSenseDataProviderTypeBD value
ename:XR_SENSE_DATA_PROVIDER_TYPE_LIGHT_ESTIMATION_BD, and chaining
slink:XrSenseDataProviderCreateInfoLightEstimationBD to
slink:XrSenseDataProviderCreateInfoBD::pname:next.

Applications use this provider handle to obtain light estimate data that is
generated by the runtime.
This data consists of spatial entities that include at least an
slink:XrSpatialEntityComponentDataLightEstimationBD component and an
slink:XrSpatialEntityComponentDataLocationBD component.

Both the elink:XrSenseDataProviderTypeBD value and the chained
slink:XrSenseDataProviderCreateInfoLightEstimationBD structure are required.
If slink:XrSenseDataProviderCreateInfoBD::pname:providerType is
ename:XR_SENSE_DATA_PROVIDER_TYPE_LIGHT_ESTIMATION_BD but no
slink:XrSenseDataProviderCreateInfoLightEstimationBD is present in the
pname:next chain of slink:XrSenseDataProviderCreateInfoBD, the runtime must:
return ename:XR_ERROR_VALIDATION_FAILURE.

The provider is configured through the
slink:XrSenseDataProviderCreateInfoLightEstimationBD structure, where
applications specify the required data types via the
elink:XrLightEstimationCreateFlagBitsBD bitmask.

If ename:XR_LIGHT_ESTIMATION_CREATE_ENVIRONMENT_TEXTURE_BIT_BD flag is set
in pname:createFlags, applications must: include an
slink:XrEnvironmentTextureCreateConfigInfoBD structure in the pname:next
chain of slink:XrSenseDataProviderCreateInfoBD.

The runtime must: not require a particular structure chaining order in the
pname:next chain of slink:XrSenseDataProviderCreateInfoBD when validating
slink:XrSenseDataProviderCreateInfoLightEstimationBD and
slink:XrEnvironmentTextureCreateConfigInfoBD.

The runtime must: not produce different validation results for different
structure chaining orders in that pname:next chain.

The runtime must: return ename:XR_ERROR_VALIDATION_FAILURE if the
ename:XR_LIGHT_ESTIMATION_CREATE_ENVIRONMENT_TEXTURE_BIT_BD flag is set in
pname:createFlags but no slink:XrEnvironmentTextureCreateConfigInfoBD is
present in the pname:next chain of slink:XrSenseDataProviderCreateInfoBD.

The runtime must: return ename:XR_ERROR_FEATURE_UNSUPPORTED if any bit in
pname:createFlags is not supported.

==== Start Light Estimation Provider

An application starts the light estimation provider by calling
flink:xrStartSenseDataProviderAsyncBD after successfully creating it.
Applications can: check the data provider state by calling
flink:xrGetSenseDataProviderStateBD.

Subsequent operations must: not be performed unless the data provider state
is ename:XR_SENSE_DATA_PROVIDER_STATE_RUNNING_BD.
If the data provider state is not
ename:XR_SENSE_DATA_PROVIDER_STATE_RUNNING_BD and the application intends to
use the provider, the application must: take appropriate action and try to
call flink:xrStartSenseDataProviderAsyncBD again before using the handle.

The definitions and usage details are described in
apiext:XR_BD_spatial_sensing.


==== Get Light Estimation Component Data

Applications can: query the latest light estimate data from the light
estimation provider by calling flink:xrQuerySenseDataAsyncBD.
The runtime then generates a snapshot of the light estimation information,
and the application can: obtain detailed light estimate data from the
snapshot through the slink:XrSpatialEntityComponentDataLightEstimationBD
structure.

Applications may: chain zero or more applicable light estimation data
structures to the
slink:XrSpatialEntityComponentDataLightEstimationBD::pname:next chain when
querying light estimate data.

If multiple applicable light estimation data structures are defined,
applications may: chain any subset of them.
Applications may: set pname:next to code:NULL to query only the
slink:XrSpatialEntityComponentDataLightEstimationBD::pname:isValid state.

To request detailed light estimate data, configure and chain the
corresponding component structures to the
slink:XrSpatialEntityComponentDataLightEstimationBD::pname:next chain:

* Chain slink:XrLightEstimationDataSphericalHarmonicsBD to be populated with
  spherical harmonics coefficients, if
  ename:XR_LIGHT_ESTIMATION_CREATE_SPHERICAL_HARMONICS_BIT_BD was passed
  during provider creation.
* Chain slink:XrLightEstimationDataEnvironmentTextureRawBD to be populated
  with environment texture data, if
  ename:XR_LIGHT_ESTIMATION_CREATE_ENVIRONMENT_TEXTURE_BIT_BD was passed
  during provider creation.

The runtime must: ignore and not populate chained structures for which the
corresponding bit was not set at provider creation.

The runtime must: populate data for all properly configured components in
the pname:next chain.

When the light estimate result changes, the runtime must: send an
slink:XrEventDataSenseDataUpdatedBD event with the handle of the light
estimation provider.
Upon receiving this event, the application can: re-query to obtain the
latest light estimate data information.
This event-driven approach is the recommended method for obtaining updated
light estimate data.

All the functions to get light estimation info are defined in
apiext:XR_BD_spatial_sensing.

When using slink:XrLightEstimationDataEnvironmentTextureRawBD to retrieve

  bytesPerPixel where resolutionWidth and resolutionHeight are derived from
  the active elink:XrEnvironmentTextureResolutionBD, and bytesPerPixel is
  defined by elink:XrEnvironmentTexturePixelFormatBD.

* Return ename:XR_ERROR_VALIDATION_FAILURE if pname:cubemapFaceBufferSize
  does not equal the expected value described above.
* Write texture data when the
  slink:XrSpatialEntityComponentDataLightEstimationBD::pname:isValid member
  returns ename:XR_TRUE.
* Write texture data according to the layout defined by the active
  elink:XrEnvironmentTextureResolutionBD and
  elink:XrEnvironmentTexturePixelFormatBD, and as illustrated in

.Member Descriptions
****

Environment Texture and Spherical Harmonics coefficients based on the sample
code in apiext:XR_BD_spatial_sensing:

PFN_xrStopSenseDataProviderBD xrStopSenseDataProviderBD;                               // previously initialized

PFN_xrQuerySenseDataAsyncBD xrQuerySenseDataAsyncBD;                                   // previously initialized
